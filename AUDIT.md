# BrowserMesh audit — agent UX and adoption

Date: 2026-09-08 · against `master` at `aec6f25` (v0.2.2)

Two axes: how well BrowserMesh serves the AI client that drives it, and what
stands between the project and wider use. Every finding below was reproduced —
by measuring the published surface, by driving the server as a client, or by
reading the repository's own state — and each names one action.

Format: `[axis] problem → proposed fix → priority`.

Priorities: **P0** costs a caller correctness or a working workflow. **P1**
costs tokens, time, or adoption. **P2** is worth doing and can wait.

## How this was measured

- `tools/list` byte sizes: an in-memory MCP client against `createMcpServer`,
  and `@playwright/mcp@latest` / `chrome-devtools-mcp@latest` over stdio, same
  machine, same day.
- Agent walkthroughs: this session drove the server over MCP against
  `https://the-internet.herokuapp.com`, headless, through `.mcp.json`.
- Project state: GitHub API, npm registry, MCP Registry, and the four largest
  `awesome-mcp-servers` lists.

## Axis 1 — Agent UX

### Errors and codes

| #   | Finding                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | Priority |
| --- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------- |
| 1.1 | **Fixed public messages carried no remediation.** `applicationErrorResult` replaces every raw message with a fixed per-code string. Correct for the boundary, but 18 of 20 codes then said only what broke. The remediation existed solely in `docs-site/reference/errors.md`, which a client choosing its next tool call never reads. → **Fixed in this change.** A constant `nextStep` per code now ships on the wire; ADR 0022.                                                                                                                                                                             | **P0**   |
| 1.2 | **A locator that matches nothing reports `OPERATION_TIMEOUT`, not `ELEMENT_NOT_FOUND`.** `performElementOperation` picks `timedOut ? OPERATION_TIMEOUT : …`, and Playwright's actionability wait always times out when nothing matches — so `ELEMENT_NOT_FOUND` is effectively unreachable for locator-driven actions. Reproduced: a valid role locator burned the full 10 s and returned "The browser operation timed out", pointing the caller at `timeoutMs`, the one remedy that cannot work. → Probe `count()` on timeout and reclassify; ADR 0025 (proposed, not applied — it changes a published code). | **P0**   |
| 1.3 | **`refs[].name` is a name the matcher rejects.** Refs carry `(aria-label ?? alt ?? title ?? textContent).replace(/\s+/gu,' ').trim()`; the role locator matches Playwright's computed accessible name with `exact: true`. Reproduced end to end: snapshot returns `{"tag":"button","name":"Login"}`, clicking `{"strategy":"role","value":"button","name":"Login"}` matches nothing, `"exact": false` succeeds instantly. BrowserMesh's own output walks the caller into 1.2. → Publish the accessible name, or mark the field as a hint that is not locator input; ADR 0025.                                  | **P0**   |
| 1.4 | **`INVALID_ARGUMENT` cannot say which argument.** The informative runtime text ("Iframe locator chain must contain between 1 and 5 selectors", "limit must be an integer between 1 and 100") is discarded for a fixed string. → Partly mitigated by 1.1's next step. Full fix: an allowlisted `field` in `details`, populated only from constants at each throw site.                                                                                                                                                                                                                                          | **P1**   |
| 1.5 | **`LOCATOR_AMBIGUOUS` does not say how ambiguous.** "matched multiple elements" — 2 and 40 need different responses. → Add `matchCount` to details; ADR 0025.                                                                                                                                                                                                                                                                                                                                                                                                                                                  | **P2**   |
| 1.6 | Two `STALE_*` codes already carried their remediation in the message. That was the model the other eighteen should have followed, and now do.                                                                                                                                                                                                                                                                                                                                                                                                                                                                  | —        |

### Tool schemas

| #    | Finding                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            | Priority |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------- |
| 1.7  | **Union-typed arguments had no prose fallback.** `locator`, `scope`, `capture`, `action`, `wait`, and `condition` are `oneOf` + `$ref` with no `description`. Observed in a real client: schema ingestion flattened them to `{"type":"object","properties":{}}`, leaving nothing anywhere in the surface from which to construct a locator. → **Fixed in this change.** Each union now carries a `.describe()` with a literal example. This costs 6,516 chars of discovery (+7.5%), which is the wrong direction for 1.12 and still the right trade: a schema the client cannot read is worth nothing at any size. | **P0**   |
| 1.8  | **The published `limit` bound contradicts the runtime.** `browser_observe`'s schema allows `limit` up to 200; `BoundedObservability` rejects anything above `maxPageSize`, default 100. A caller obeying the schema gets `INVALID_ARGUMENT` with a message that cannot say why. → Derive the schema bound from configuration, or lower the schema to 100 and document the raise.                                                                                                                                                                                                                                   | **P1**   |
| 1.9  | **Three names for one cursor.** `browser_snapshot` returns `pagination.nextCursor` and takes `cursor`. `browser_observe` returns `nextCursor` and takes `sinceEventId`, whose value is also an `eventId`. → Accept `cursor` as an alias on `browser_observe` and name the concept once in both descriptions.                                                                                                                                                                                                                                                                                                       | **P1**   |
| 1.10 | **Element-target naming is consistent; composite naming is not.** `browser_click` and the other 18 element actions all take `locator`/`ref` — good. `browser_action_and_wait` nests the same thing as `action.target`, and `browser_drag_and_drop` uses `source`/`target` where `target` is a locator, not an `ElementTarget`. → Document the distinction in both descriptions; renaming is a breaking change and not obviously worth it.                                                                                                                                                                          | **P2**   |
| 1.11 | **Session IDs cost more than they need to.** `session_6d3d71be-c74a-4b28-8dcc-2b653b11ec7e` plus `page_7d91597e-…` is ~85 characters of arguments on every page call, echoed again in every result. A 50-call workflow spends several thousand tokens on addressing alone — the direct price of the explicit-addressing invariant. → A shorter opaque form (`s_6d3d71be`) keeps the invariant and unguessability at a quarter of the bytes. Breaking for anything that stored an ID.                                                                                                                               | **P2**   |

### Discovery cost

| #    | Finding                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    | Priority |
| ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------- |
| 1.12 | **The surface is 4.7× Playwright MCP.** Measured `tools/list` before this change: BrowserMesh 35 tools / 87,259 chars; `--tools core` 31 / 79,394; `chrome-devtools-mcp` 29 / 25,130; `@playwright/mcp` 24 / 18,477. Roughly 22,000 tokens of every client's context before the first browser call. The descriptions added for 1.7 take it to 93,775 / 85,910, so the case below is now stronger, not weaker. → ADR 0024 (proposed): a committed ceiling checked by a test, optional output schemas, a `minimal` profile, a 400-character description cap. | **P1**   |
| 1.13 | **Output schemas are 35% of the surface (30,827 chars) and are BrowserMesh's alone** — Playwright MCP publishes 48 chars in total. Three session tools each restate the whole `sessionView` including `contextSettings` (2,033 chars each); nineteen element actions each publish 353 chars to say `{completed: true}`. Blocked by SPEC §22.2. → ADR 0024.                                                                                                                                                                                                 | **P1**   |
| 1.14 | **`--tools core` is not actually narrow.** It is "everything that is not observability or persistence": 31 of 35 tools, 91% of the bytes. The profile mechanism exists but has no profile that meaningfully uses it. → Add `minimal`; ADR 0024.                                                                                                                                                                                                                                                                                                            | **P1**   |

### Limit consistency

Full table: `docs-site/reference/limits.md`, added in this change. It did not
exist; the numbers were spread across `resource-limits.ts`, `snapshots.ts`,
`config.ts`, and one constant in the Playwright adapter.

| #    | Finding                                                                                                                                                                                                                                                                                                                                                                                                                                                                          | Priority |
| ---- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------- |
| 1.22 | **`browser_runtime_info` under-reports the limits it exists to report.** It returns session, screenshot, visible-text, and persistence bounds — not snapshot bounds, not observability bounds, not the two 30-second TTLs. `LIMIT_EXCEEDED` and `INVALID_ARGUMENT` now say so on the wire rather than sending callers there for bounds it will not return, which is a disclosure, not a fix. → Extend `resourceLimits` with the snapshot and observability groups and both TTLs. | **P1**   |
| 1.23 | **`browser_visible_text` truncation is terminal.** No per-call bound argument, no cursor: at `truncation.truncated` the caller has no in-protocol remedy, while `browser_snapshot` paginates. The defaults also disagree — 20,000 chars against the snapshot's 50,000 — so the same page yields different budgets depending on how it is read. → Give it `maxChars`/`maxBytes` arguments, or say in the description that the remedy is a narrower locator. Documented for now.   | **P1**   |
| 1.24 | **The two 30-second TTLs are independent constants that happen to agree.** `ELEMENT_REF_TTL_MS` lives in the Playwright adapter, `cursorTtlMs` in `domain/snapshots.ts`. Nothing keeps them equal and nothing reports either. → One domain constant, reported by `browser_runtime_info`.                                                                                                                                                                                         | **P2**   |
| 1.25 | `maxChars` and `maxBytes` bind on different content — the byte bound hits at ~21,800 characters of three-byte text — so identical arguments return less on a CJK page. Correctly reported via `byMaxChars`/`byMaxBytes`; it was simply undocumented. → Documented.                                                                                                                                                                                                               | ✅       |
| 1.26 | `partial: true` is well handled: `nextCursor`, `expiresAt`, `offsetChars`, and the full `truncation` block all arrive together. The gap was naming (1.9), not information.                                                                                                                                                                                                                                                                                                       | ✅       |

### Trust friction

| #   | Finding                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | Priority |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------- |
| 2.4 | **The GitHub star preflight is the project's largest adoption risk.** A security review reads the capability, not the etiquette: a dependency instructing the agent to make authenticated writes to the developer's GitHub account, by default, on connect. ## Applied in this change

- `nextStep` on every error result, one constant per code (ADR 0022), with an
  exhaustive-`Record` type and a test over `errorCodes`.
- `.describe()` with a literal example on `locator`, `capture`, `condition`,
  `action`, and `wait`.
- `compare_page_states` and `form_validation` prompts, with tests.
- `docs-site/reference/limits.md` — every bound in one table, first time.
- `docs-site/reference/errors.md` rewritten to quote the wire strings.
- README: comparison table, badges, cold-start warm-up.

## Left for the maintainer

ADR 0023 (support-request default), ADR 0024 (discovery-cost budget), and
ADR 0025 (element-action failure classification) are all `Proposed` with no code
attached. Each changes a shipped default, a published contract, or a SPEC
requirement. The two repository-settings items — 2.2 and 2.10 — and the failed
release in 2.7 need account access this audit does not have.
